# PRD：AI 热点日报 v6（2026-10-10，已确认）

> 状态：**已确认**（2026-10-10，qiao 授权贾维斯拍板，第 8 节的四个问题均按产品建议执行）。各功能按里程碑拆分 Issue。
> 基线：现状版 v5（线上 https://ai-daily.qiao-ai-daily.workers.dev ）。

## 1. 目标
一句话定位：**每天 5 分钟，用中文看懂 X 上的 AI 圈**。要可信、精美、方便转发。
- **G1 精美统一**：有统一的品牌（Logo / VI）和视觉规范，所有页面和分享图都遵守，克制、不“AI 味”。
- **G2 读得更快**：打开首页 30 秒内就能知道今天最重要的三件事。
- **G3 看得更深**：每个话题都能看到来龙去脉，包括持续了几天、热度怎么变化、和哪些话题有关。
- **G4 愿意转发**：每天一张、每个话题一张的分享图，发到微信或 X 都好看。
- **G5 工程可维护**：标准、主流的前后端工程结构，有完整的自动化测试，能安全迭代。
- **延续 v5 的原则**：数据真实不编造，Cloudflare 免费额度内运行，每日更新不需要重新部署。

## 2. 用户与场景
| 用户 | 场景 |
|---|---|
| qiao（主要） | 早上在手机上看当天日报；在电脑上回看、搜索；把好内容转发出去 |
| 朋友 / 同事（次要） | 从分享的图片或链接进来，只读浏览 |

## 3. 功能需求

### 3.0 网址与服务端输出（F1–F5 共用）
| 页面 | 网址 | 说明 |
|---|---|---|
| 今日 | `/` | 最新一天 |
| 某天日报 | `/day/YYYY-MM-DD` | 日期不存在时返回 404 页 |
| 话题详情 | `/story/<story-id>` | id 即数据里的 `id`（带日期前缀，如 `2026-10-10-claude-dashboards-motion`），作为对外链接**长期有效**；id 不存在时返回 **404 页**，不能回落到首页 |
| 搜索 | `/search?q=` | |
| 往期 | `/archive`、`/archive?tab=trend`、`/archive?tab=weekly&week=YYYY-Www` | 日期列表、趋势、周报 |
| 我的 | `/me` | 收藏和关注 |
- **旧网址兼容**：
  | 旧网址 | 新网址 | 方式 |
  |---|---|---|
  | `/trend` | `/archive?tab=trend` | Worker 返回 301 |
  | `/fav` | `/me` | Worker 返回 301 |
  | `/?d=YYYY-MM-DD` | `/day/YYYY-MM-DD` | 前端 `location.replace`（Worker 的路由按路径匹配，看不到查询参数；首页要保持静态缓存） |
  | v5 的 `#v=…`、`#/…` | 对应新网址 | 前端 `location.replace`（`#` 后面的内容不会发给服务器） |
  - 前端跳转用 UI 测试验证最终地址，服务端跳转用 curl 验证状态码和 `Location`。
- **404**：日期不存在或格式错误、话题 id 不存在时，返回真正的 404 状态码和 404 页，HTML 里**不输出 og 标签**。404 页的说明文案（如“日报从 X 月 X 日开始”）中的最早日期从 `/api/days` 动态读取，不写死。
- `/assets/` 下不存在的静态文件返回 404 加 `no-store`，不能回落到首页 HTML。
- 对 `/`、`/day/*`、`/story/*` 和周报页，**由 Worker 在 HTML 里直接输出**该页的 `og:title`、`og:description`、`og:image`、`og:url` 和 `twitter:card=summary_large_image`，因为爬虫不执行 JS。图片暂未生成时（F3 上线前，或者当天预生成还没完成），`og:image` 指向一张静态的默认品牌图（Logo），不能为空。
- **验收**：不执行 JS，直接 `curl /story/<id>`，返回的 HTML 里有上述标签；`og:image` 地址请求后返回 200，类型是 `image/png`；`curl /story/不存在的id` 和 `curl /day/2000-01-01` 都返回 404。

### 3.1 跨日匹配规则（F1 的标记、F2 的走势和关联话题共用）
话题 id 每天都不同，所以按 `topics` 匹配，不按 id。
1. **宽泛词**不参与匹配，包括两类：
   - 维护在 `packages/shared/src/streaks.ts` 里的黑名单（以代码为准），包括：
     - 大公司和机构名，如 `OpenAI`、`Anthropic`、`Google`、`Meta`、`微软`、`腾讯`；
     - 横跨多件事的人名，如 `马斯克`、`特朗普`、`奥特曼`、`黄仁勋`；
     - 模型家族或品牌名，如 `ChatGPT`、`GPT`、`Claude`、`Gemini`、`Grok`、`Llama`、`Qwen`、`DeepSeek`（具体型号如 `GPT-6`、`Gemini 4`、`Codex` 仍算具体 topic）；
     - 全部分类名；
     - 泛称和领域词，如 `大模型`、`开源模型`、`AI智能体`、`AI安全`、`AI就业`、`AI医疗`、`美国政策`、`预测市场`。
     - 中小公司名（如 `Broadcom`、`Super Micro`）不进黑名单。
   - **按天单独判定**的高频词：在某一天里出现在 3 个及以上话题中的 topic，在**这一天**算宽泛词。
   - 比较之前先做规范化：NFKC（统一全角和半角）、去掉所有空白、转小写。
2. 今天的话题 S 和过去某天 D 的话题 T，只要共享一个 topic t，并且 t 不在黑名单里、在今天和 D 天都不算宽泛词，就算匹配。D 天有任意一个话题和 S 匹配，D 就记为 S“出现过”的一天，当天热度取匹配话题里最高的 `heat`。
3. **连续天数 N**：只按**有日报的日期**来数，没有日报的日子（比如漏采）直接跳过，不算中断。从今天往前数，遇到第一个有日报但没出现过的日子就停下。N 包含今天。
4. 标签规则：N ≥ 2 标“持续热议 N 天”。N = 1，并且过去 30 天里从没出现过，标“新”。如果话题**没有任何具体 topic**（全是宽泛词），因为没法判断，**不加任何标签**；详情页的走势显示单天空状态，关联话题改用“同一个 `org_tag` 的近 7 天话题”。
5. **采集规范**（由贾维斯负责，从 2026-10-11 那期开始执行）：每条话题的 `topics` 里**至少有 1 个具体的产品名或事件名**（例如 `Claude Dashboards`、`星舰`），不能只写公司名和泛称；同一件事跨天必须用同一个写法。每日 JSON 的格式不变。

**验收例子**（测试夹具要用具体 topic，不能用 `OpenAI` 这种黑名单词）：
| 数据 | 期望 |
|---|---|
| 10-08、10-09、10-10 都有话题包含 `Codex` | 10-10 的这个话题标“持续热议 3 天”，走势 3 个点，每个点取当天最高的 heat |
| 10-08 有 `Codex`，10-09 没有日报，10-10 有 `Codex` | 跳过 10-09，标“持续热议 2 天” |
| 10-08 有 `Codex`，10-09 有日报但没有 `Codex`，10-10 有 `Codex` | N = 1；30 天内出现过，所以不标“新”，也不加任何标签 |
| 话题的 topics 只有 `OpenAI`、`大模型` | 不加标签 |
| 10-10 有 3 个话题都含 `星舰` | `星舰` 当天算宽泛词，不靠它匹配 |

### F1 首页改版（P0）
- 顶部是日期切换和“**今日三件事**”：取当天 JSON 中 `highlights` 的前 3 条，**不改每日数据格式**。
- 话题卡片带“新”或“持续热议 N 天”标签（按 3.1 的规则），并显示热度条（0–100）、机构标签和分类。
- **排序**：默认按数据里的 `rank`（编辑排序，和 v5 一致）。
- 保留 v5 已有的分类筛选、历史日期、搜索、收藏、趋势、导出和主题切换（默认浅色，不跟随系统；手动切换后记住选择）。
- **验收**：
  - 手机 390px 宽的首屏能看到“今日三件事”和第一张卡片。
  - 视觉：4 种组合（手机/电脑 × 浅色/深色）和高保真稿（PR #13）的基准截图对比通过。
  - 功能：v5 的回归清单（现有 UI 测试和 API 黑盒测试）全部通过。
  - 标签：3.1 的验收例子全部通过。

### F2 话题详情页（P0）
- 网址是 `/story/<id>`（见 3.0），可以直接打开、刷新和分享，服务端输出 OG 标签。
- 内容依次是标题、摘要、为什么重要、热度走势、全部 X 原帖（含译文和互动数）、新闻链接、数据说明、关联话题（最多 5 个）。
- 热度走势只用真实的每日 `heat`，范围是最近 30 天里有日报的日子；只有 1 个点时显示“首次出现”，**不画假走势**。
- 关联话题：过去 30 天里和它共享具体 topic 的其他话题，同一件事只保留最新那天的；按共享的具体 topic 数从多到少排序，数量相同时按日期从新到旧。
- **验收**：用多天测试夹具核对，走势的点数和数值与数据库一致；单日数据时显示空状态；3.0 的 curl 验收通过。

### F3 分享图（P1）
- 两种尺寸，共用一套模板和同一个渲染函数，只是版式不同（贾维斯 2026-10-10 确认）：
  - **横版 1200×630**：用作 `og:image`，适配 X 和微信的链接预览（X 会把大图裁成约 1.91:1）。
  - **竖版 1080×1440**：给“保存图片”按钮用，适合手机转发。
- 每日卡片：日期、今日三件事、Logo、网址和二维码。话题卡片：标题、摘要节选、热度、日期、Logo 和二维码。只做浅色一版，字体只用思源黑体和 Inter 的子集。
- **生成方式**：免费版 Worker 每个请求只有 10ms CPU，不能在线上实时渲染。所以在每天 `daily.sh` 跑完之后，**另起一个独立的预生成脚本**，为当天的每日卡片和每个话题渲染两种尺寸的 PNG，存进 **Workers KV**（绑定名 `CARDS`，不开 R2），内部 key 是 `card/{kind}/{id 或日期}/{og|save}.png`，180 天后过期。分享卡随时能重新生成，过期清理只针对卡片，日报数据一条都不删。Worker 只负责读取和返回这些图片，不在线渲染。`daily.sh` 本身不改（红线）；预生成脚本 `node scripts/prerender-cards.mjs <日期> --env production|preview` 接在它后面，失败只记日志、不影响日报，接入每日流程由贾维斯负责。
- 对外图片网址（KV 的 key 不对外暴露）：`/og/day/<date>.png`、`/og/story/<id>.png` 是横版，在后面加 `?size=portrait` 取竖版。返回规则：
  1. 日期或话题存在，KV 里也有图：返回这张图，可以长缓存。
  2. 日期或话题存在，但 KV 里还没有图：返回默认品牌图（Logo B 加“AI 热点日报”，横版和竖版各一张，见设计 PR #24），状态码 200，类型 `image/png`，**只缓存几分钟**，等预生成完成后自动换成真图。
  3. 日期或话题不存在：返回 404。
- 二维码四周的留白至少 4 个模块宽（见设计规范）。
- **验收**：尺寸准确；中文不缺字、不出现方框；`og:image` 返回 200 和 `image/png`；X 的 Card Validator 或分享预览能显示图片；手机上能保存竖版图片；预生成脚本可以对任意一天重复执行，结果一致。

### F4 关注（P2）
- 可以关注三种对象：
  - X 账号：匹配原帖的 `handle`；
  - 机构：匹配 `org_tag`；
  - 关键词：匹配 `headline_zh`、`summary_zh`、`topics`，以及原帖的 `text` 和 `translation_zh`，不区分大小写。
- 首页高亮命中的话题，提供“只看关注”筛选；在“我的”页面里管理关注。最多关注 50 个。
- **只存在本机浏览器（localStorage）里，不登录、不上传**，换设备不同步。
- **验收**：关注和取消关注后刷新仍然保持；上面三种匹配各有用例覆盖；达到 50 个上限时有提示；没有关注任何内容时有引导性的空状态。

### F5 周报（P2）
- 一周按北京时间周一 00:00 到周日 24:00 计算，用 ISO 周编号。从已有数据**实时计算**，不新增采集。
- **Top 10**：一周里所有话题按 `heat` 从高到低排序，同一件事（按 3.1 规则匹配）只保留热度最高的那一条；热度相同时按日期从新到旧。
- **反复出现的话题**：本周有 2 天或以上出现过的具体 topic，按出现天数排序。
- 本周还没过完时，显示“截至今天”；本周没有任何数据时显示空状态。
- **验收**：周报里的数字都能从每日数据复算出来，跨周边界（周日到周一）的用例要覆盖。

### 3.2 接口（只新增，不修改现有接口）
| 路径 | 用途 | 主要返回字段 |
|---|---|---|
| `GET /api/stories/:id` | 话题详情 | 话题全部字段（含 `source_posts`、`news_refs`、`data_quality`）、`date`、`badge`（`new` / `ongoing` / 无）、`streak_days` |
| `GET /api/stories/:id/trend` | 热度走势 | `points: [{date, heat, story_id}]` |
| `GET /api/stories/:id/related` | 关联话题 | `stories: [{id, date, headline_zh, heat, shared_topics}]`，最多 5 条 |
| `GET /api/weekly?week=YYYY-Www` | 周报 | `week`、`from`、`to`、`partial`、`top: [...]`、`recurring_topics: [{topic, days}]` |
| `GET /og/day/:date.png`、`GET /og/story/:id.png` | 分享图 | PNG |
- 首页卡片需要的 `badge` 和 `streak_days`，可以加进 `/api/days/:date` 的返回里，**只能新增字段，不能改动现有字段**。
- 不存在的 id、日期或周，接口统一返回 JSON 404。

## 3.3 信息架构（与设计对齐）
- 手机底部标签栏有四个：今日、往期、搜索、我的。往期页顶部可以切换“趋势”和“周报”；“我的”里放收藏和关注。电脑端用侧边导航，结构与手机一致。
- 字体：网页优先用系统字体，其他设备回退到思源黑体 + Inter；分享图一律嵌入思源黑体 + Inter 的子集。

## 4. 品牌与视觉要求（交给设计，由 qiao 拍板）
- 先定 Logo / VI 和视觉规范，再出 UI 页面设计；所有页面和分享图共用一套规范（颜色、字号、间距、组件）。
- 已定方向：现代、柔和的苹果风格，主色是紫色（浅色模式 `#7D5AF0`，深色模式 `#A88BFF`，紫色文字用 `#6440D6`），Logo 用方案 B。详细规范以 `docs/design/` 为准（PR #5）。
- 克制、不“AI 味”：不用紫蓝渐变、发光、满屏 emoji、大圆角胶囊这类套路。
- 手机优先；浅色和深色两套主题都要完整设计。

## 5. 工程要求（非功能）
- 前端：Vite + React + TypeScript + Tailwind 4。后端：Hono 跑在 Cloudflare Workers 上。数据库沿用 D1。代码组织成 monorepo，前后端共用类型和数据 schema。
- **兼容性红线**：现有 API 的路径和返回格式不变；`daily.sh`、`json2sql`、D1 表结构和每日 JSON 格式都不变。每天 8:50 的数据更新不能断。
- 参数统一校验：修掉已知的 6 个接口 bug，任何输入都不能返回 500，其余现有行为保持不变（例如 `from`/`to` 不合法时忽略，`limit=abc` 用默认值）。
- 测试：单元测试、组件测试、API 黑盒测试、端到端测试，以及 4 种组合（手机/电脑 × 浅色/深色）的截图对比，全部纳入本地 CI 并且都要通过。
- 部署：生产和预览分成两套环境；发布前备份；能在几分钟内回滚。坚持在 Cloudflare 免费额度内运行，新增任何付费资源都需要 qiao 批准。
- 性能：用 Lighthouse 移动端（Slow 4G 模拟）测首页，LCP ≤ 2 秒；前端首包 gzip 后 ≤ 60KB，并在 CI 里设体积上限检查（见 #16）。
