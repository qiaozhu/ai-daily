# Roadmap（v1 草案，2026-10-10，待 qiao 拍板）

> 来源：2026-10-10 团队讨论（测试 / 部署 / 开发 / 设计 / 协调 bot 的建议）。
> 原则：**先打地基，再做“精美”**。A 组（质量和基础设施）的 P0 是 B 组所有新功能的前置条件。
> 排期后的每一项都要开 Issue，走 `docs/workflow.md` 的流程（新功能先 PRD → qiao 签字）。

## 现状要点（影响排序）
- 线上目前只有 **1 天** 数据（`/api/days` 仅 2026-10-10）。热度走势、关联话题、趋势都要多天数据才有意义，所以 **每日数据稳定积累** 是 B 组走势类功能的前置条件；开发和测试阶段可以先用 `tests/fixtures/` 里的多天数据。
- 后端集中在 147 行的 `src/worker.js`，前端为原生 JS + CSS（共约 565 行），继续不引入框架（开发 bot 建议，产品同意）。
- 测试 bot 已发现 6 个接口 bug（如非法 URL 编码、`limit=1.5` 返回 500）。

| P2 | 今日要点可折叠摘要、每日推送（邮件/IM）、自定义域名 | — | — | 留在想法池 |

## 建议的里程碑
1. **M1 打地基**：A-P0-1 → A-P0-2，并行 A-P0-3、B-P0-1。
2. **M2 好看又可靠**：A-P1-4、A-P1-5、B-P1-3 分享卡片（不依赖多天数据，可先做）。
3. **M3 有深度**：B-P1-2 话题详情页 + 热度走势（此时已有一周以上数据）。
4. **M4 个性化**：B-P2-4 订阅（范围由 qiao 决定后再写 PRD）。

## 需要 qiao 拍板
1. 以上优先级和里程碑顺序是否同意。
2. 订阅的范围：先做**无登录版**（订阅存在本机浏览器里，不碰账号和隐私数据），还是直接做**账号版**（需要登录、D1 新表，并修改 PRD 的非目标）。产品建议先做无登录版。
3. 预览环境如果需要新增 Cloudflare 资源，是否同意（目前目标是全部在免费额度内）。
4. 失败告警 / 每日推送用什么渠道（邮件、IM 或其他）。
