# PRD：AI 热点日报（现状版 v5，2026-10-10）

> 状态：已上线 · 负责人：qiao · 线上：https://ai-daily.qiao-ai-daily.workers.dev
> 下一版需求见 [`PRD-v6.md`](PRD-v6.md)（2026-10-10 确认）。
> 本文描述**当前已实现**的产品，作为后续需求（Issue）的基线。新需求请走 `docs/workflow.md` 的流程。

## 1. 背景与目标
qiao 希望每天快速了解 X（Twitter）上最热的 AI 资讯，用中文阅读，并能回看历史。
- **G1** 每天一份中文日报：8–12 个去重后的热点话题，按热度/新闻价值排序。
- **G2** 可信：每条结论都能点回 X 原帖；互动数、链接均为真实抓取数据，不编造。
- **G3** 可积累：历史日报长期保存，可搜索、可收藏、可看趋势。
- **G4** 低成本、免运维：Cloudflare 免费额度内运行；每日更新只推数据，不需要重新部署。

## 2. 用户
- **主要用户**：qiao（中文读者，桌面 + 手机都会看）。
- **次要**：qiao 分享链接的朋友/同事（只读；目前收藏是全站共享的，见非目标）。

## 3. 功能（已实现）
| 模块 | 说明 |
|---|---|
| 今日日报 | 默认打开最新一天；按排名列出话题卡片（#1…#N）。每张卡片：中文标题、机构标签、分类、热度、若干条 X 原帖卡片。 |
| X 原帖卡片 | 头像首字母、显示名、@handle、发帖时间（由 snowflake ID 精确换算，UTC+8）、原文、中文译文（“译”标记）、回复/转发/点赞/浏览；整卡点击新标签打开 x.com 原帖。 |
| AI 摘要 | 桌面：右侧吸顶面板，显示选中话题的摘要、为什么重要、数据说明、X 新闻链接、收藏按钮；点击任一话题切换。手机：摘要卡在每个话题卡片内、原帖下方。 |
| 历史日报 | 桌面左侧日期列表；平板/手机为顶部日期下拉框。 |
| 分类筛选 | 分类 chips（带数量），作用于当前列表（日报/搜索/收藏）。 |
| 搜索 | 跨全部日期搜索标题、摘要、为什么重要、标签、原帖原文与译文（多词 AND），关键词高亮；搜索页顶部有输入框。 |
| 收藏 | ☆ 收藏保存在服务器（D1），任何设备可见；“收藏”页列出全部收藏。 |
| 趋势 | 每日分类分布、分类累计（近 7 天）、跨日反复出现的话题（不足 2 天时显示热门话题）；话题可点击搜索。 |
| 导出 | `/api/export` 下载全部日报 + 收藏的 JSON。 |
| 主题 | 浅色（默认，不跟随系统）/ 深色；左侧导航与手机顶栏可切换，记在 localStorage。 |
| 数据说明 | 每天的数据质量备注显示在列表底部；单条话题的数据问题显示在摘要里。 |
| 可分享 URL | 视图/日期/分类/搜索词写入 URL hash（`#v=search&q=...`）。 |

## 4. 非目标（当前）
- 多用户账号、个人收藏（收藏目前全站共享，无登录）。
- 实时更新 / 推送通知（每天一次）。
- 英文界面、非 X 数据源。
- 评论、点赞等社交功能。

## 5. 数据源
- **X 公开数据**，通过 Grok Bot 的 X 工具采集：`search_news`（X 新闻聚合）+ `search_posts_all`（官方账号 `from:` 查询、中文圈 `lang:zh` 查询、按新闻话题找代表帖）。
- 限额：30 次/分钟、1000 次/天、每次 ≤25 条；不支持 `min_faves` 等操作符。
- 只用工具返回的真实数据；X 新闻（Grok 生成摘要）可能有误，只有新闻无高互动原帖的话题要在 `data_quality` 中注明；忽略泄露密钥、诈骗、纯广告帖。
- 详细查询清单与 JSON 字段：`docs/product/data-pipeline.md`、`tools/day_template.json`。

## 6. 每日流程（pipeline）
1. **采集**（约 15–25 次 X 工具调用，时间窗约最近 24h）。
2. **编写当天 JSON**：`$DATA_DIR/YYYY-MM-DD.json`（默认 `/workspace/ai-digest/data`），去重归并 8–12 个话题，写中文标题/摘要/为什么重要/分类/话题/热度/原帖与译文。
3. **推送数据**：`bash scripts/daily.sh YYYY-MM-DD` → 校验 JSON → 生成幂等 SQL → 写入远程 D1（只替换该天，不动其他天和收藏）。
4. **交付**：把线上地址发给 qiao。前端从 API 读数据，**无需重新部署**。
5. （建议）把当天 JSON 通过 PR 同步进仓库 `data/` 快照。

热度公式：`heat = min(100, 12*log10(1 + max(likes + 2*reposts + views/200)) + 3*帖子数)`。

## 7. 架构
Cloudflare Worker（`src/worker.js`，API）+ Workers Static Assets（`public/`，前端）+ D1（SQLite）。
API：`/api/health`、`/api/days`、`/api/days/:date|latest`、`/api/stories?q=&category=&from=&to=`、`/api/trends`、`/api/favorites`（GET/POST/DELETE）、`/api/export`。
**唯一的公开写接口是收藏**（同源校验、JSON、故事须存在、每 IP 30 次/分钟、总量上限 2000）。数据导入只走 wrangler + API token，没有公开 ingest 接口。

## 8. 成功指标（定性）
- 每天按时更新；打开即看到当天内容；手机可读。
- 每条话题至少 1 条可点击的 X 原帖；无编造数据。
